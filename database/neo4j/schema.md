# KFM-AE Neo4j Graph Schema Documentation\n\nThis document describes the Neo4j graph schema used for tracking agent relationships and dependencies in the KFM-Agentic Evolution (KFM-AE) system. Core agent data is stored in PostgreSQL.\n\n**Target Database:** Neo4j 4.4+\n\n## Graph Model Overview\n\nThe graph models agents as nodes and their interactions/dependencies as relationships. This allows for efficient traversal and analysis of complex connections like dependency chains and evolutionary lineage.\n\n## Node Labels and Properties\n\n### `:Agent` (Primary Label)\n\nRepresents any managed agentic entity in the system.\n\n**Properties:**\n\n*   `unique_id` (String - UUID format, Required, Unique): The primary identifier linking this node to the corresponding record in the PostgreSQL `Agents` table.\n*   `type` (String, Required): The type of the agent (e.g., \'Software Artifact\', \'AI Model\'). Duplicated from Postgres for filtering. Should match the secondary label.\n*   `version` (String, Required): The version identifier of the agent. Duplicated from Postgres.\n*   `status` (String, Required): The current lifecycle state (e.g., \'STABLE\', \'EXPERIMENTAL\'). Duplicated from the Postgres `lifecycle_state` for filtering.\n\n### Secondary Labels (Based on `type`)\n\nAdditional labels are applied based on the agent\'s `type` property to allow for type-specific querying.\n\n*   `:SoftwareArtifact`\n*   `:AIModel`\n*   `:DataStructure`\n*   `:AutonomousSystem`\n*   *(Potentially others as defined in PRD 3.1)*\n\nExample Node Creation (via Sync Service):\n\n```cypher\nMERGE (a:Agent {unique_id: $agent_unique_id})\nON CREATE SET a.type = $agent_type, a.version = $agent_version, a.status = $agent_status\nON MATCH SET a.type = $agent_type, a.version = $agent_version, a.status = $agent_status\n// Add secondary label based on type\nCALL apoc.create.addLabels(a, [$agent_type_as_label]) YIELD node\nRETURN node;\n```\n\n## Relationship Types and Properties\n\nRelationships connect `:Agent` nodes.\n\n### `:DEPENDS_ON`\n\nIndicates that one agent requires another agent to function.\n\n*   Direction: `(Dependent:Agent) -[:DEPENDS_ON]-> (Dependency:Agent)`\n*   **Properties:**\n    *   `created_at` (Datetime, Required): Timestamp when the dependency was established.\n    *   `description` (String, Optional): Textual description of the dependency nature.\n    *   `metadata` (Map, Optional): Arbitrary key-value pairs for additional context.\n\n### `:EVOLVED_FROM`\n\nTracks the version lineage or derivation history of an agent.\n\n*   Direction: `(NewVersion:Agent) -[:EVOLVED_FROM]-> (OldVersion:Agent)`\n*   **Properties:**\n    *   `created_at` (Datetime, Required): Timestamp when the new version was created/branched.\n    *   `change_type` (String, Optional): Type of change (e.g., \'Patch\', \'Minor\', \'Experiment\').\n    *   `description` (String, Optional): Link to commit hash, change log, or description of the evolution.\n\n### `:COMPOSED_OF`\n\nLinks a composite agent to its constituent parts.\n\n*   Direction: `(CompositeAgent:Agent) -[:COMPOSED_OF]-> (PartAgent:Agent)`\n*   **Properties:**\n    *   `created_at` (Datetime, Required): Timestamp when the composition was defined.\n    *   `role` (String, Optional): Describes the function of the part within the composite.\n\n### `:EXTENDS`\n\nRepresents inheritance, implementation, or template-based relationships.\n\n*   Direction: `(Child:Agent) -[:EXTENDS]-> (Parent:Agent)`\n*   **Properties:**\n    *   `created_at` (Datetime, Required): Timestamp when the extension relationship was defined.\n    *   `description` (String, Optional): Details about the nature of the extension (e.g., \'Implements interface X\').\n\n## Constraints\n\n*   `unique_agent_id`: Ensures `unique_id` property is unique for all nodes with the `:Agent` label.\n    ```cypher\n    CREATE CONSTRAINT unique_agent_id IF NOT EXISTS FOR (a:Agent) REQUIRE a.unique_id IS UNIQUE;\n    ```\n\n## Indexes\n\n*   `agent_unique_id_index`: On `(:Agent {unique_id})`. Supports fast node lookup by `unique_id`. Often created automatically by the unique constraint.\n    ```cypher\n    CREATE INDEX agent_unique_id_index IF NOT EXISTS FOR (a:Agent) ON (a.unique_id);\n    ```\n*   `agent_type_index`: On `(:Agent {type})`. Supports efficient filtering by `type`.\n    ```cypher\n    CREATE INDEX agent_type_index IF NOT EXISTS FOR (a:Agent) ON (a.type);\n    ```\n*   `agent_status_index`: On `(:Agent {status})`. Supports efficient filtering by agent status (lifecycle state).\n    ```cypher\n    CREATE INDEX agent_status_index IF NOT EXISTS FOR (a:Agent) ON (a.status);\n    ```\n*   `agent_version_index`: On `(:Agent {version})`. Supports efficient lookup by `version`.\n    ```cypher\n    CREATE INDEX agent_version_index IF NOT EXISTS FOR (a:Agent) ON (a.version);\n    ```\n\n## Benefits of Graph Model (vs. Relational for Relationships)\n\n*   **Complex Dependency Chains:** Efficient multi-hop traversals (`MATCH (start)-[:DEPENDS_ON*1..]->(dep)`).\n*   **Impact Analysis:** Easy backward traversal to find dependents (`MATCH (dependent)-[:DEPENDS_ON*]->(target)`).\n*   **Lineage Tracking:** Simple traversal of `:EVOLVED_FROM` relationships.\n*   **Pattern Discovery:** Native Cypher support for complex pattern matching (e.g., circular dependencies).\n```
